# 对抗性审查规范

## 目标

只寻找足以使本次分析结果不可信的重大错误。不要把审查变成“建议再做十个稳健性检验”的扩展清单。

## 输入

- 用户原始分析要求；
- 分析设计清单；
- 数据质量摘要；
- 变量对应表；
- 所有最终 `.inp`；
- 所有 `.out`；
- 结构化模型比较结果；
- SAVEDATA 解析结果；
- 最终分析报告；
- 使用到的 Source Registry 条目。

## 必查项

1. 用户要求的分析与实际分析是否一致；
2. 剖面指标是否使用了错误变量；
3. 原始样本数、分析样本数与 Mplus 输出样本数是否合理一致；
4. 变量映射是否出现错位或重复；
5. LPA 基础模板是否被未经授权改变；
6. 是否存在被忽略的 Mplus ERROR；
7. 最佳 loglikelihood 未重复却被当成稳定模型；
8. TECH14 有可信度警告却被报告为有效；
9. 报告中的 AIC/BIC/SABIC/Entropy/类别比例是否与 `.out` 一致；
10. 推荐类别数的文字理由是否与比较表矛盾；
11. SAVEDATA 中 ID 与原始数据是否能够一一对应；
12. 是否把启发式阈值写成公认硬标准。

## 输出规则

- 无重大问题：返回机器状态 `PASS`，不生成用户可见审查报告。
- 有重大问题：返回 `FAIL` 并列出每个问题的证据位置、影响和是否可自动修复。
- 能自动修复的错误应先修复并重新运行分析，再重新审查。
