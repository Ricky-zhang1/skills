# 结构化分析设计

非 LPA 标准模块使用 JSON 设计清单。用户不需要手写 JSON；Agent 根据对话和数据生成，再调用 `run-spec`。

缺失值可用命令行声明全局缺失码。不同变量采用不同编码时，在设计中写 `"missing_by_variable": {"score": [99], "income": [-9]}`；如果 `99` 对年龄等变量是合法值，写 `"confirmed_valid_values": {"age": [99]}`。同一变量的同一数值不能同时声明为缺失和有效。

描述统计、信度、相关和差异分析改用 `preliminary --spec 设计.json --data 数据文件 --output 新目录`。

## 初步统计

```json
{"analysis":"reliability","scales":{"学业投入":["q1","q2","q3"]},"items_aligned":true}
```

```json
{"analysis":"difference","outcomes":["投入","压力"],"group":"性别","posthoc":true}
```

## CFA

```json
{
  "analysis": "cfa",
  "variables": ["x1", "x2", "x3", "y1", "y2", "y3"],
  "categorical": [],
  "factors": {
    "学业投入": ["x1", "x2", "x3"],
    "学校归属": ["y1", "y2", "y3"]
  }
}
```

## SEM

```json
{
  "analysis": "sem",
  "variables": ["x1", "x2", "x3", "y1", "y2", "y3"],
  "factors": {
    "投入": ["x1", "x2", "x3"],
    "归属": ["y1", "y2", "y3"]
  },
  "regressions": [
    {"outcome": "归属", "predictors": ["投入"]}
  ]
}
```

## 观测变量 Bootstrap 中介

```json
{
  "analysis": "mediation",
  "variables": ["x", "m", "y"],
  "factors": {},
  "regressions": [
    {"outcome": "m", "predictors": ["x"]},
    {"outcome": "y", "predictors": ["m", "x"]}
  ],
  "indirect": [
    {"outcome": "y", "predictor": "x", "mediator": "m"}
  ],
  "bootstrap": 5000
}
```

`indirect.mediators` 可以按理论顺序放入多个中介，用于链式中介。并列中介应分别建立多条 `indirect`，不能把并列关系写成链式顺序。

## 多元与 Logistic 回归

连续结果使用 `analysis: regression`。二分类结果使用 `analysis: logistic`，并同时提供 `outcome`，只把结果变量写进 `categorical`。分类预测变量应先建立有明确参照组的虚拟变量或对比编码。

## 观测变量调节与有调节的中介

```json
{
  "analysis": "moderated-mediation",
  "variables": ["x", "w", "m", "y"],
  "interactions": [{"name": "xw", "left": "x", "right": "w", "center": "grandmean"}],
  "regressions": [
    {"outcome": "m", "predictors": ["x", "w", "xw"], "labels": {"x": "a", "xw": "aw"}},
    {"outcome": "y", "predictors": ["m", "x", "w"], "labels": {"m": "b"}}
  ],
  "conditional_indirect": {
    "a_label": "a", "interaction_label": "aw", "b_label": "b",
    "moderator_values": {"indlow": -1, "indmean": 0, "indhigh": 1}
  },
  "bootstrap": 5000
}
```

条件值必须来自有意义的量尺位置或已确认的均值和标准差。`-1/0/1` 只在变量已经标准化或这些数值本身有含义时使用。

## 基础 CLPM

```json
{
  "analysis": "clpm",
  "variables": ["x1", "x2", "x3", "y1", "y2", "y3"],
  "panels": {"x": ["x1", "x2", "x3"], "y": ["y1", "y2", "y3"]},
  "equal_lagged": false
}
```

基础入口要求两个变量具有相同且不少于三个波次。它生成自回归、交叉滞后和同期协方差，不替代 RI-CLPM。

## 基础两层模型

```json
{
  "analysis": "multilevel",
  "confirmed_guided": true,
  "variables": ["school", "x", "w", "y"],
  "cluster": "school",
  "within_variables": ["x"],
  "between_variables": ["w"],
  "centering": {"x": "groupmean", "w": "grandmean"},
  "within_regressions": [{"outcome": "y", "predictors": ["x"]}],
  "between_regressions": [{"outcome": "y", "predictors": ["w"]}]
}
```

未列入 `within_variables` 或 `between_variables` 的结果变量可以在两层都有变异。每个观测预测变量必须在 `centering` 中明确写 `groupmean`、`grandmean` 或 `none`；Runtime 会真实生成 `DEFINE: CENTER`，不会把“已确认中心化”只当备注保存。跨层调节通过 `random_slopes` 建立个体层随机斜率，再在 `between_regressions` 中用群体层变量预测该斜率。

## 基础增长模型

```json
{
  "analysis": "growth",
  "variables": ["t1", "t2", "t3", "t4"],
  "repeated": ["t1", "t2", "t3", "t4"],
  "time_scores": [0, 1, 2, 3]
}
```

## 调用

EFA 要把某个因子解作为后续解释对象时，在设计中明确写入 `selected_factors`：

```json
{
  "analysis": "efa",
  "variables": ["x1", "x2", "x3", "x4", "x5", "x6"],
  "min_factors": 1,
  "max_factors": 3,
  "selected_factors": 2
}
```

`selected_factors` 不是让 Runtime 自动选解。它记录研究者结合平行分析、碎石图、拟合、载荷和理论后要解释的因子数；未填写时，报告会提醒不要直接进入 CFA/SEM。

LCA 比较 1-5 类时使用：

```json
{
  "analysis": "lca",
  "variables": ["u1", "u2", "u3", "u4"],
  "categorical": ["u1", "u2", "u3", "u4"],
  "class_counts": [1, 2, 3, 4, 5]
}
```

运行命令：

```bash
./scripts/运行Mplus分析.sh run-spec \
  --spec "分析设计.json" \
  --data "数据.xlsx" \
  --self-test-receipt "Mplus安装自检/Mplus自检凭证.json" \
  --output "Mplus分析项目"
```
