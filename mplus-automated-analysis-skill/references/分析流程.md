# 用户侧标准工作流

用户只需要提供数据并说明分析需求。Agent 应尽可能自行从文件识别信息，只有真正无法确定的研究设定才询问。

LPA 标准流程：

1. 检测本机 Mplus 与版本；默认先运行自检。自检暂不能完成时，只有用户明确同意才以“未自检试运行”继续，并在报告中标明；
2. 读取数据并识别变量；
3. 建立《分析设计清单》；
4. 数据质量检查；
5. 生成 Mplus 安全变量名与 `.dat`；
6. 生成 1—5 类 `.inp`；
7. 批量运行初筛模型；
8. 检查最佳 loglikelihood 是否重复；
9. 对不稳定模型升级随机起始值；
10. 对稳定模型运行类别比较测试；
11. 解析 `.out` 和 SAVEDATA；
12. 形成模型比较表和候选推荐；
13. 生成中文分析报告和代码逐段说明；
14. 运行程序化硬检查；
15. 调用独立对抗性审查；
16. 无重大问题则正常交付；有重大问题则生成质量审查报告。样本量、类别规模、未自检试运行等提示不自动否决模型，但不能被省略。
